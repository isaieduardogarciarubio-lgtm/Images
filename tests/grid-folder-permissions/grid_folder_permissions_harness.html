Grid QA Harness — Permisos de Carpetas (Folders API)

Basado en Biblia de Desarrollo en Grid V11.4 — Sección 13 (Folders API)

⚠️ Este harness crea y borra carpetas reales en tu cuenta de Grid. Los objetos de prueba se nombran con el prefijo QA_HARNESS_ para poder identificarlos y limpiarlos. Si vas a probar la asociación documento↔carpeta, usá un doc_id descartable — el borrado de una carpeta es recursivo y también soft-elimina los documentos que contiene, por eso este harness siempre desvincula el documento (DELETE /folders/{id}/documents/{doc_id}) antes de borrar la carpeta de prueba.

2. Suite A — Dueño de la carpeta (automática, corre con tu sesión)

Crea una carpeta de prueba, valida CRUD, roles (owner/editor/viewer), ACL, límite de nesting y asociación de documentos. No requiere segunda cuenta.

2b. Diagnóstico — PUT /permissions devuelve 422 "Invalid values in body object"

En una corrida real (2026-07-07) PUT /folders/{id}/permissions falló con HTTP 422 {"error":"Invalid values in body object."} usando un folder_id recién creado y válido — descarta la explicación de la Biblia V11.3 ("era un folder_id obsoleto"). Este bloque corre variantes de body (LDAP vs email, con/sin historial de sharing previo, claves opcionales omitidas) para aislar la causa real. Requiere haber corrido la Suite A primero (usa su carpeta y su segundo usuario).

3. Suite B — Colaborador (permisos negativos, requiere segunda sesión LDAP)

Suite A comparte la carpeta creada con el usuario indicado en "segundo usuario" arriba, primero como viewer y luego lo promueve a editor. Para validar que las restricciones de rol se cumplen de verdad, esa otra persona debe abrir este mismo HTML en su propia sesión de Grid, pegar el folder_id que le paso el dueño abajo, y correr esta suite — se espera que reciba 403 en las operaciones que su rol no permite.
